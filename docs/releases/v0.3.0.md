# Copilot and Azure Usage Monitor v0.3.0

## Changes since v0.2.5

- Optional Public Azure monitoring, off by default. When enabled, the desktop
  widget shows GitHub Copilot and Azure together; the main panel offers source tabs.
- Azure subscription selection, local budgets, amount alerts, environment checks
  and rediscovery. Configure Azure CLI profiles with the `az-profile-switch`
  (azure-profile-switch) skill first. Azure China and confirmed invalid profiles
  are not displayed. Missing prerequisites and permissions show actionable checks.
- Each Azure subscription retains its reporting period, currency and alert dedup.
  Costs are never added to Copilot, converted across currencies or treated as a
  real-time balance/final invoice. Billing-period fallback remains explicit.
- Settings now use GitHub Copilot / Azure / Updates & About tabs. Authentication
  actions belong to Copilot; updates, the prominent version and shared privacy
  information are consolidated. The main panel also has an EN / 中 switch.
- Content-sized main panel stays visible during manual resizing. Stable settings
  scrollbar space avoids horizontal jumps. Widget refresh shows Reading and
  automatic size changes no longer cumulatively move its preferred position up.
- Preserve v0.2.5 viewport/drag fixes, authentication, autostart, technical App ID,
  executable name, settings/profile paths and production update channel/key.

## Download and update

Download `Copilot.Usage.Monitor.exe` or the portable ZIP. Compatible v0.2.3–v0.2.5
and revised fixed-name v0.2.2 clients can check, explicitly download and confirm
Restart and update. The combined Updates & About page must show **0.3.0**.
Azure remains off until enabled; existing Copilot settings/login are retained.
Exit the old copy before manually running a new one. Do not overwrite an
installer-managed EXE. Moving the portable EXE requires refreshing autostart.

Windows 10/11 x64 and WebView2 Runtime required; Azure CLI is needed only for
Azure monitoring. No installer or automatic prerequisite installation.
**Windows Authenticode: NotSigned.** Ed25519 update signing authenticates the
manifest and exact EXE bytes, not Windows execution approval. Do not bypass
SmartScreen or corporate policies. Public downloads grant no internal service
or Azure subscription access. No source, credentials or real billing data are
included in the portable package.

## Privacy and verification scope

Observed usage/costs stay in memory, without application telemetry. Settings and
reminder dedup are local. WebView2 manages Copilot authentication; Azure CLI
manages Azure authentication. CLI calls explicitly set `AZURE_CONFIG_DIR` and do
not change external default subscriptions/clouds, copy credentials, automatically
log in or clear caches. Remote portal pages cannot invoke Azure commands.
Windows, WebView2 and CLI may write their own caches/diagnostics. Updates use
public GitHub without an update token, observed usage or internal cookies.

Automated frontend/Rust tests, native synthetic WebView2 checks, portable
diagnostics and signed-artifact validation cover the integrated build. Synthetic
screenshots are not real sign-in or billing evidence. Real mixed-DPI monitor
moves, corporate policy, Windows notifications and an actual public-channel UI
upgrade remain target-environment acceptance; do not equate local/headless
checks with that full acceptance.
