# Copilot and Azure Usage Monitor v0.3.1

## Changes since v0.3.0

- Fix the main panel disappearing when starting a title-bar drag. Preserve native
  resizing and ordinary hide-on-focus-loss behavior.
- Stabilize compact/expanded widget geometry near screen edges. Apply position
  and size together and skip unchanged geometry to avoid visible bouncing.
- Use two saved appearance modes: light purple and dark purple. Both the main
  panel and Settings have a language button followed by a split-circle theme
  button. Legacy light tones map to light purple; no settings identity migration.
- Use one bordered refresh button for the active GitHub Copilot or Azure source;
  Settings has a matching border. Add balanced separators between subscriptions
  in the panel and expanded widget.
- Refine expanded Azure rows: smaller subscription names, larger bold amounts,
  compact gray reporting dates, and the budget percentage beside the amount.
  Budget text turns orange only above the matching-currency alert amount.
- Keep previous Azure costs visible while reading. Publish new amounts before
  fetching service details, using at most two workers. Access the same resolved
  CLI profile serially, including aliases and fallback identities. Subscription
  order stays fixed; failed refreshes label retained costs and never alert on them.
- Refresh the homepage guide and screenshots using the current frontend and
  synthetic data, including the dark mode and reading state.

## Download and update

Download `Copilot.Usage.Monitor.exe` or `CopilotUsageMonitor-v0.3.1-windows-x64.zip`.
Compatible update-enabled clients can check, explicitly download and confirm
Restart and update. Updates & About must show **0.3.1** after upgrading. Existing
Copilot and Azure preferences, authentication and App ID remain unchanged; Azure
stays opt-in. Quit the old copy before manually starting another one.

Windows 10/11 x64 and WebView2 Runtime required. Azure CLI is required only for
Azure monitoring. No installer, automatic login or prerequisite installation.
**Windows Authenticode: NotSigned.** Ed25519 authenticates the update manifest
and exact EXE bytes; it is not Windows execution approval. Do not bypass company
security controls. Public downloads grant no internal-service or Azure access.

## Security and verification scope

Usage and costs stay in application memory. Preferences and alert dedup are
local. Every CLI child receives an explicit `AZURE_CONFIG_DIR`; external default
subscription, cloud and login state are not deliberately changed. No credentials
are copied, no automatic login/cache clearing is performed, and remote webpages
cannot invoke Azure commands. Periods, currencies and notification dedup remain
separate. Windows, WebView2 and CLI may write their own caches/diagnostics.

Local tests and synthetic native WebView2 checks cover progressive refresh,
failure retention, disable/cancellation, appearance and widget geometry. These
do not measure live Azure speed or prove real public-channel UI upgrade,
corporate policy, notifications or mixed-DPI monitor movement. Initial profile
discovery remains serial; concurrency targets subscription cost refreshes.
