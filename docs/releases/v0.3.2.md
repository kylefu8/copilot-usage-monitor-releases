# Copilot and Azure Usage Monitor v0.3.2

## Changes since v0.3.1

- Add Settings > Azure > **Copy setup prompt**. The complete offline prompt
  embeds the English Azure profile skill and Windows reference; no skill
  installation or source-repository access is needed first.
- Explain where to run the prompt: Copilot CLI, Agency, Codex or another trusted
  local agent with command execution. The app only copies text and never runs
  installation, sign-in or profile-management commands.
- Start the prompt with read-only checks. Installation, fresh profiles and
  interactive sign-in require approval. Approved sign-in opens a visible
  PowerShell window; warnings or launcher completion are not proof of login
  failure. Finish the account loop before returning to app verification.
- Provide complete English and Chinese standalone `az-profile-switch` skills,
  with their repository-relative paths visible in Settings. These can be used
  independently to add or manage profiles without the full Bootstrap.
- Add a Global English getting-started guide, manual setup option, second-PC
  verification checklist and approval-gated test cleanup prompt. Refresh the
  homepage documentation and synthetic onboarding screenshots.
- Distinguish setup problems, transient checks, selection and cost permissions.
  Copied diagnostics contain only allowlisted codes, setup state and version,
  never real account names, paths, subscription IDs or billing amounts.
- Keep environment diagnostics in the selected language when switching languages.

## Download and update

Download `Copilot.Usage.Monitor.exe` or `CopilotUsageMonitor-v0.3.2-windows-x64.zip`.
Compatible update-enabled clients can check, explicitly download and confirm
Restart and update. Updates & About must show **0.3.2** after upgrading. The App
ID, local settings, Copilot authentication and Azure profile references do not
change. Azure remains off by default for new users. Quit an old copy before
manually starting another; all normal copies share data and single-instance state.

Windows 10/11 x64 and WebView2 Runtime are required. Azure CLI is required only
for Azure monitoring. No installer or automatic prerequisite installation.
**Windows Authenticode: NotSigned.** The Ed25519 update signature authenticates
the exact EXE bytes, not Windows execution approval. Do not bypass company
security policy. Public download grants no internal-service or Azure permissions.

## Safety and verification scope

The app preserves the existing authentication and security boundaries. Every
Azure CLI child gets an explicit `AZURE_CONFIG_DIR`. No credential copying,
automatic login/cache clearing or mutation of external profiles' default
subscription/cloud is introduced. Remote web content gets no Azure-management
capability. Periods, currencies and alert dedup remain independent.

The optional agent workflow operates outside the app and still requires users
to review and approve changes. Its instructions are not a guarantee that every
agent will behave identically. Cleanup inventories first and removes only exact
approved test targets; it is not a factory reset and does not clear shared SSO.

Automated checks cover offline prompt parity, visible-login launcher construction,
account-loop ordering, bilingual skill command parity, safe copy diagnostics,
clipboard fallback and language handling. Screenshots use synthetic data, not
real accounts. These checks do not prove every agent, real Azure login/cost
permissions, corporate policy or a real public-channel UI upgrade on another PC.
Use the [second-PC checklist](../verify-on-another-pc.md) for target-environment
acceptance; do not clear real profiles to manufacture missing-prerequisite states.
